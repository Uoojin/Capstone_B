# 노트북 모달 크기 및 PROJECT 문단 폭 수정

이번 요청에서 바꾼 소스는 CSS 4개이며, 모두 기존 **1025~1599px** 노트북 구간에 한정됩니다. JSX·상태·이벤트·데이터·이미지 경로는 수정하지 않았습니다. 이번 요청 시작 시점의 기존 작업 폴더를 비교 기준으로 사용했습니다.

## GUESTBOOK 포토부스

문제 원인은 촬영 모달에도 적용되는 공통 `overflow-y: auto`와, 업로드 툴팁의 음수 `right` 오프셋 조합입니다. 툴팁은 투명해도 레이아웃의 가로 스크롤 영역에 포함될 수 있었습니다. 촬영 버튼 그리드의 첫 컬럼도 기본 min-content 크기를 유지하고 있었습니다.

수정은 촬영 모달에만 적용합니다.

- 너비: `min(100%, 812px, (100dvh - 280px) × 1.25 + 36px)`.
- 원래 카메라 미리보기 비율 1.25:1 유지.
- 모달과 바깥 X를 세로 flex 묶음으로 중앙 정렬. X의 별도 align-self도 중앙으로 지정.
- 툴팁 `right: 0`으로 모달 안에 배치.
- 촬영 버튼 컬럼 `minmax(0, 1fr)` 및 필요한 자식의 min-width 정리.
- 크기가 맞는 촬영 모달은 overflow를 visible로 사용. `overflow-x: hidden`으로 가리지 않음.

촬영 이후 편집·프리뷰·QR 단계는 새 CSS 선택자와 일치하지 않습니다. 기존 버튼의 디자인·카메라·업로드·타이머 로직은 그대로입니다.

## SYNCOPATE

제작 모달의 기존 `--modal-width`만 다음과 같이 변경했습니다.

- 이전: `min(1190px, 78vw, (100dvh - 168px) × 1190 / 626)`
- 현재: `min(1000px, 66vw, (100dvh - 200px) × 1190 / 626)`

기존의 폭 기반 내부 치수 계산을 그대로 사용합니다. 좌측 캔버스/우측 패널의 1.59:1 컬럼, TOOLS·SYMBOL·SIZE·SPACING·COLOR·MESSAGE·공유 순서, 색상·아이콘·폰트 스타일을 재작성하지 않았습니다. 주요 세 노트북 크기에서는 외곽 비율도 약 1.901로 유지됩니다. 작은 경계 크기에서는 기존 최소 글자 크기의 영향으로 높이가 조금 늘어날 수 있으나 버튼과 X는 화면 안에 있습니다.

오브젝트 상세 카드 너비는 `min(340px, 24vw, (100svh - 200px) × .70)`로 줄였습니다. 이미지의 정사각 프레임과 원본 object-fit, 본문·정보·닫기 디자인은 유지했습니다.

| 뷰포트 | 제작 모달 너비 전→후 | 상세 카드 너비 전→후 |
|---|---:|---:|
| 1512×982 | 약 1179→998px | 390→340px |
| 1440×900 | 약 1123→950px | 390→340px |
| 1366×768 | 약 1065→902px | 약 382→328px |

## PROJECT 상세 설명

이전 `width: calc(100% + 8vw)`가 문단을 컬럼 밖으로 지나치게 펼쳤습니다. 그 규칙만 아래처럼 바꿨습니다.

```css
width: min(100%, max(480px, 33vw));
max-width: 100%;
```

주요 노트북에서 약 480~499px, 1025px 경계에서는 중앙 컬럼 너비인 약 476px로 제한됩니다. 문단의 왼쪽 정렬선은 그대로이고 오른쪽 카테고리까지 펼쳐지지 않습니다.

폰트 크기·줄간격·본문·그리드·이미지·스크롤은 변경하지 않았습니다. 줄바꿈 삽입, line-clamp, 말줄임표, 내용 잘라내기는 없습니다. 31vw는 일부 긴 본문을 5줄로 만들었지만, 선택한 공통 폭은 현재 17개 프로젝트의 전문을 모두 최대 4줄로 표시했습니다.

## 실제 브라우저 검증

Chrome의 CSS 뷰포트를 지정하고 DPR 2로 확인했습니다. 실제 사용자 Chrome 창을 직접 읽은 결과는 아닙니다.

| CSS 뷰포트 | 포토부스 가로 넘침 | 설명 최대 줄 수 | 설명 전문 |
|---|---:|---:|---|
| 1512×982 | 0px | 4줄 | 17개 모두 일치 |
| 1440×900 | 0px | 4줄 | 17개 모두 일치 |
| 1366×768 | 0px | 4줄 | 17개 모두 일치 |
| 1280×640 | 0px | 4줄 | 17개 모두 일치 |
| 1025×700 | 0px | 4줄 | 17개 모두 일치 |

- 포토부스: 툴팁 hover 상태에서도 모달 clientWidth와 scrollWidth 일치. 모달·버튼·X 모두 화면 안에 위치.
- X의 가로 중심이 뷰포트 중앙과 일치. 모달/X 그룹의 세로 중심 오차 0.01px 이하.
- 가상 카메라로 실제 미리보기 스트림 및 5초 카운트다운→촬영→편집 단계 확인. 실제 사용자의 카메라는 사용하지 않았음.
- 다섯 크기에서 테스트용 로컬 PNG 업로드→편집 단계 확인. 외부 서버에 게시하지 않았음.
- 제작 모달: 캔버스/패널 비율 약 1.59:1, 공유/X 화면 안 표시, 그룹 중앙 정렬 확인.
- 드로잉 전후 PNG가 달라짐, 되돌리기는 시작 PNG와 일치, 다시 실행은 그리기 후 PNG와 일치.
- 상세 모달은 테스트 브라우저의 API 응답으로 제공한 오브젝트를 실제 클릭해 확인. 정사각 이미지·중앙 정렬·X 접근 확인. 서버 데이터 변경 없음.
- PROJECT: 현재 17개 데이터를 5개 크기에서 총 85번 측정. 모든 본문 전문 일치, 최대 4줄.

## PC·태블릿·모바일 보존

이번 수정 전 CSS를 같은 DOM에 다시 적용해 주요 계산 스타일을 비교했습니다.

- PC: 1920×1080, 1800×1169
- 태블릿: 1024×768, 820×1180, 768×1024
- 모바일: 767×850, 390×844, 375×812

PC·태블릿은 포토부스·제작 모달·PROJECT 상세, 모바일은 기존에 접근 가능한 PROJECT 상세를 비교했습니다. **총 18개 조합에서 차이 0건**입니다. 이것은 주요 계산 스타일 비교이며 모든 애니메이션 프레임의 픽셀 비교는 아닙니다.

- `npm run lint`: 통과.
- `npm run build`: 통과. 기존 번들 크기 경고 유지.
- 수정한 4개 파일 `git diff --check`: 통과.

## 산출물과 제한

- `task-changes.patch`: 이번 요청에서 수정한 내용만 포함.
- `before/`: 비교에 사용한 원본 CSS.
- `paragraph-probe.json`: 문단 폭 후보별 실제 줄 수.
- `results.json`: 기능·크기·본문 검증. 포토부스의 최종 X 가로 정렬은 다음 파일 기준.
- `final-checks.json`: 최종 포토부스 위치와 18개 보존 비교.
- `photo-final-*.png`: 최종 포토부스 캡처. 초록색 화면은 브라우저의 가상 카메라 영상이며 실제 사이트 이미지가 아님.
- `drawing-*.png`, `object-*.png`, `paragraph-*.png`: 제작·상세 모달과 문단 캡처.

카메라 하드웨어/OS 권한 대화상자, 실제 서버 공유·저장 게시까지 수행한 검사는 아닙니다. 관련 소스와 이벤트 로직은 수정하지 않았습니다. 데이터에 이미지가 비어 있는 프로젝트는 기존 플레이스홀더로 표시됩니다.
