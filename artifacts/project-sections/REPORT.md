# PROJECT 상세 — 섹션 정렬 및 본문 폭 수정

## 수정 파일과 범위

이번 요청에서 수정한 소스는 두 개뿐입니다.

- `src/pages/Project/Project.css`
- `src/pages/Project/Project.jsx`

새 동작은 기존 노트북 구간인 **1025~1599px 상세페이지 내부**에만 적용됩니다. PROJECT 목록·필터·캐러셀·프로젝트 데이터·이미지 경로·순서·이전/다음 연결·폰트·색상·헤더·다른 페이지는 이번에 수정하지 않았습니다. 기존 작업 폴더의 다른 미커밋 변경도 보존했습니다.

`task-changes.patch`는 이번 요청을 받았을 때의 파일과 비교한 변경만 포함합니다.

## 원인

1. 소개 섹션의 최소 높이가 `100svh - 72px`이라 첫 화면 하단에 다음 TEAM 섹션이 들어올 수 있었습니다.
2. 기존 상세 휠 보간은 입력한 거리만큼 이동하고 멈추므로 TEAM 시작점이 화면 상단과 어긋난 상태에 머무를 수 있었습니다.
3. 설명의 `max-width: 31vw`가 중앙 컬럼보다 좁아 긴 본문에서 불필요한 줄바꿈이 생겼습니다.

## 수정 내용

### 독립 섹션과 시작점

노트북 소개의 `min-height`를 `100svh`로 변경했습니다. 고정 `height`가 아니므로 내용이 더 길면 자연스럽게 늘어납니다.

상세 스크롤 컨테이너에 `scroll-snap-type: y mandatory`, 각 섹션에 `scroll-snap-align: start`와 `scroll-snap-stop: always`를 적용했습니다. 이전의 하단 scroll-padding은 시작 기준을 흐리지 않도록 0으로 정리했습니다. 화면 전체 높이의 실제 스크롤 영역과 기존 TEAM 하단 내비게이션 여유 공간은 유지했습니다.

기존 JS가 매 프레임 `scrollTop`을 쓰면 브라우저 스냅과 충돌할 수 있어, 해당 상세 휠 핸들러에서 노트북 구간만 기본 브라우저 스크롤로 넘깁니다. PC·태블릿·모바일의 기존 처리와 다른 휠 핸들러는 그대로입니다. 새로운 커스텀 이동 애니메이션이나 섹션 강제 점프 함수를 추가하지 않았습니다.

섹션이 이동하는 동안에는 일반적인 스크롤 전환이 일어나며, **입력이 끝나 정렬된 상태에서 각 섹션의 시작점이 정확히 맞습니다.** 콘텐츠를 숨기거나 교체해서 다른 섹션을 감추는 방식은 사용하지 않았습니다.

### 본문 전문 4줄 이내

폰트 크기·줄간격·본문 내용을 바꾸지 않았습니다. 폭을 `calc(100% + 8vw)`로 넓히고 31vw 상한을 해제했습니다. 중앙의 왼쪽 정렬선은 유지하고, 카테고리 위쪽에 비어 있는 컬럼 간격을 활용합니다. 본문의 오른쪽 끝은 카테고리 컬럼보다 앞에 위치합니다.

`line-clamp`, 말줄임표, 본문 overflow 잘라내기는 추가하지 않았습니다. 현재 등록된 17개 프로젝트의 전문을 모두 표시합니다. PC·태블릿·모바일의 기존 본문 폭은 변경하지 않았습니다.

| 1512×982 | 17 | 3줄 | 모두 일치 | 0건 |
| 1440×900 | 17 | 3줄 | 모두 일치 | 0건 |
| 1366×768 | 17 | 3줄 | 모두 일치 | 0건 |

총 85개 본문을 DOM Range의 실제 줄 위치로 측정했습니다. 표시된 textContent는 공통 데이터에서 읽은 설명 전문과 동일합니다. 모든 소개 화면에서 TEAM 시작점이 뷰포트 아래에 있어 다음 섹션이 걸쳐 보이지 않았습니다.

### 실제 휠 왕복 검사

1512×982, 1440×900, 1366×768에서 각각 17개 프로젝트, 총 51개를 실제 `mouse.wheel` 입력으로 아래/위 왕복했습니다.

- 아래 스크롤 종료 후 TEAM 상단 0px: 실패 0건.
- 위 스크롤 종료 후 소개 상단 0px: 실패 0건.
- TEAM 정렬 후 이전 소개 영역의 하단이 화면에 남는 경우: 0건.
- 큰 팀 이미지 상단이 화면 밖에 있는 경우: 0건.
- 큰 이미지·작은 이미지·팀원 목록이 하단 내비게이션과 겹치는 경우: 0건.
- 프로젝트별 이동 후 소개 시작 위치 초기화 및 기존 이전/다음 버튼으로 17개 프로젝트 순회 확인.

이미지 크기·비율을 추가로 줄이거나 늘리지 않았습니다.

### 긴 소개의 내부 탐색

현재 공통 상세 컴포넌트는 대표 이미지 슬롯 하나를 렌더링합니다. 이미지 데이터·경로 또는 순서는 변경하지 않았습니다.

화면보다 긴 소개가 스냅 때문에 건너뛰어지는지 확인하기 위해, 테스트 브라우저 DOM에만 650px 높이의 패널 두 개를 추가했습니다. 소개는 약 2042px로 늘어났으며, 휠 입력에 따라 scrollTop이 `0 → 250 → 500 → 750 → 500 → 250 → 0`으로 이동했습니다. 내부 중간 위치를 자유롭게 탐색하고 되돌아올 수 있었고 TEAM으로 즉시 점프하지 않았습니다. 테스트 패널은 실제 소스나 데이터에 추가하지 않았습니다.

## 보존 검사

이번 수정 전 CSS를 동일 DOM에 다시 적용해 주요 계산 스타일을 비교했습니다.

- 1920×1080, 1800×1169
- 1024×768, 820×1180, 768×1024
- 767×850, 390×844, 375×812

각 크기에서 PROJECT 목록과 열린 상세를 확인한 **16개 상태 비교 모두 차이 0건**입니다. 노트북 3개 크기의 목록 화면에서도 차이는 비활성 상세의 `detail-scroller` 속성에만 있었으며, 목록 요소의 스타일 변화는 없었습니다.

계산 스타일 비교는 모든 애니메이션 프레임의 픽셀 비교를 의미하지 않습니다. 이미지가 등록되지 않은 데이터는 기존 플레이스홀더로 남아 있습니다.

- `npm run lint`: 통과.
- `npm run build`: 통과. 기존 큰 번들 경고 유지.
- 수정한 두 파일의 `git diff --check`: 통과.
