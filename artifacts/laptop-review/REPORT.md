# 노트북 전용 서브페이지 수정

이 보고서의 보존 기준은 이번 요청을 받았을 때의 작업 폴더입니다. 앞선 작업의 태블릿 디자인과 기존 미커밋 변경을 포함하여 그대로 보존했습니다.

## 적용 범위와 코드 보호

새 CSS는 모두 다음 구간에만 적용됩니다.

```css
@media (min-width: 1025px) and (max-width: 1599px)
```

하한은 기존 태블릿의 마지막 경계인 1024px 다음입니다. 상한은 이미 사용 중인 중간 화면 구간의 1599px을 유지했습니다. 1500px이나 물리적 디스플레이 해상도를 임의의 기준으로 쓰지 않았습니다. 1600px 이상도 기존 디자인을 유지하므로, 요청한 1800~1920px은 수정 대상에서 제외됩니다.

HOME 관련 파일, 전역 CSS, App, Footer, 데이터, 이미지, 라우팅, 랜덤/정렬, 스크롤 및 애니메이션 로직은 이번에 수정하지 않았습니다. 새 헤더 스타일은 `site-header--subpage` 클래스가 있는 헤더에만 적용됩니다. 이 클래스는 기존 pathname을 읽어 표시 여부만 구분하며, 메뉴 로직은 바꾸지 않습니다. 전체 scale/zoom이나 콘텐츠를 숨기는 방식은 사용하지 않았습니다.

## 원인과 수정

### PROJECT 목록

기존 스크롤 애니메이션은 목록 섹션 상단을 화면 상단에 맞춥니다. 기존 중간 화면의 filter margin-top은 0이고 목록 padding-top은 48px이라, 높이 80px인 sticky 헤더와 겹칠 수 있었습니다.

스크롤 계산은 그대로 두고 목록의 padding-top을 `var(--site-header-height) + 24~36px`로 확보했습니다. 실제 유도 버튼을 눌러 도착한 상태에서 필터 y좌표는 약 104~110px, 헤더 하단은 80px이었습니다. 카드 3열과 오른쪽 고정 순서 목록은 유지했습니다.

### PROJECT 소개 및 TEAM

소개는 PC의 컬럼 비율인 14.8:46.4:14.8과 9vw 간격을 사용합니다. 설명은 중앙에서 최대 31vw로 읽기 폭을 확보하고, 부제목·설명·이미지의 왼쪽 정렬선을 맞췄습니다. 폰트는 노트북 폭에 맞게 줄였습니다.

대표 이미지는 원래 비율 890:600을 유지하며, 너비와 `svh`를 함께 반영합니다. 고정 absolute top으로 이미지를 밀어 넣지 않습니다. 이번 테스트 데이터에서는 모든 소개 이미지 하단에 접근할 수 있었으며, 더 긴 콘텐츠가 추가되어 한 화면을 넘으면 기존 detail-scroller가 정상적으로 스크롤합니다.

상세 스크롤러는 하단 탐색용 72px을 제외한 높이를 사용합니다. 이전/다음 버튼은 이 여유 공간에 남아 있습니다. TEAM 중앙 이미지는 `min(48.94vw, 100svh - 120px)`으로 높이를 제한하고, 팀원 간격은 화면 높이에 대응합니다. 팀명·작은 이미지의 왼쪽 위치, 중앙 이미지, 오른쪽 팀원이라는 구성을 유지합니다.

### SYNCOPATE 및 기타 서브페이지

HOW TO SYNC 안내와 설명·추가 버튼을 각각 작은 폰트·패딩·가장자리 여백으로 조정했습니다. 드로잉 모달은 최대 66vw/1050px 너비, 내부 캔버스 프레임은 화면 높이에 따라 400~480px을 사용합니다. 기본 캔버스 해상도와 좌표·히스토리·공유 로직은 변경하지 않았습니다.

메시지·사진 보기 모달과 Guestbook 메시지 모달은 화면 높이에 맞춘 크기 및 스크롤을 사용합니다. Curriculum은 이미 폭 비례 구조가 있어 첫 화면의 세로 여백을 주로 보정했고, Behind는 고정 px 제목·명단·간격을 노트북에 맞게 조정했습니다.

## 브라우저 검증

로컬 Vite 서버에서 Chrome을 실행해 CSS 뷰포트와 `devicePixelRatio`, `visualViewport.scale`, `screen`, `outerWidth/outerHeight`를 읽었습니다. 테스트 DPR은 2, visualViewport.scale은 1입니다. 이것은 제어된 테스트 환경의 값이며 사용자가 열어 둔 Chrome의 실제 설정을 읽은 결과가 아닙니다.

## 남아 있는 확인 사항

1. **실제 사용자 Chrome의 innerWidth/innerHeight·확대 배율은 아직 미확인입니다.** 사용 중인 Chrome이 도구에 연결되어 있지 않아 해당 창을 직접 읽을 수 없었습니다. 채팅에서 실제 측정값을 요청했습니다. 그 값이 도착하면 위 테스트와 별도로 동일 CSS 크기에서 재검증할 수 있습니다. 현재 결과를 실제 맥북 창에서 직접 검증한 것으로 주장하지 않습니다.
2. 데이터에 이미지와 일부 학생·팀원 정보가 비어 있어 캡처에는 플레이스홀더나 빈 칸이 있습니다. 이번 작업에서 콘텐츠와 에셋은 수정하지 않았습니다.
3. 한 화면에 들어갈 수 없는 향후 긴 콘텐츠는 내부 스크롤로 접근합니다. 콘텐츠를 숨겨 한 화면에 억지로 맞추지 않습니다.
4. 선택한 Chrome 사용자 설정, 실제 브라우저 확대 비율, 사이드 패널 등에 따라 CSS 뷰포트는 달라질 수 있습니다. DPR만으로 브라우저 확대 비율을 단정하지 않았습니다.
